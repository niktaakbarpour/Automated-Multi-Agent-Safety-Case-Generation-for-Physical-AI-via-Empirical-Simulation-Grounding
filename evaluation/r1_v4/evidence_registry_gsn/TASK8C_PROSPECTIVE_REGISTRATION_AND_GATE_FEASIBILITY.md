# Prospective Task 8C source registration and R1 gate feasibility

**Status: architecture and feasibility proposal only. No recording, annotation, or empirical admission is authorized by this document.** The frozen R1 v3 requirement, Checker, configuration, and nine physical admission gates remain unchanged.

## Decision and target-domain boundary

Keep RegistryV3 2.1.0 immutable as a development-only source extension. The existing Task 8C pulse/sham source groups have been used for adapter and registry development and cannot become an independent holdout by changing a flag or relabeling their cohort metadata.

The Task 8C external-force domain can validate source parsing, native bindings, timing, contact extraction, and event measurements under controlled perturbation. It does not validate whether the policy naturally causes or prevents a fall: an external intervention is causally distinct from policy execution. Therefore, these recordings must remain a **measurement-validation domain**, separate from empirical R1 safety-case admission. Natural policy-execution failures require their own prospective cohort, policy/action provenance, and separately powered evaluation.

**Recommendation: NO-GO this week for new recordings intended to establish R1 empirical admission or Checker performance.** The current source cannot close several admission gates, and a one-week sample cannot supply the missing method validation by itself. A small, prospectively approved engineering study could assess extraction feasibility, but it must be labelled development/measurement validation and cannot support admission. No data collection or annotation is started here.

## Prospective registration architecture

Do not add a `development_only=false` option to schema 2.1.0. If a protocol is later approved, implement a separately versioned RegistryV3 source and evaluation contract (proposed record schema **3.0.0**) with these components:

1. **Protocol receipt:** immutable approved protocol identifier and hash, target domain, source-selection rule, measurement and exclusion rules, reviewer plan, sample-size/uncertainty plan, and predeclared analysis. No free-form registry setting can declare a cohort independent.
2. **Cohort enrollment and separation:** an authority-signed receipt created before predictions or references are opened. It binds source-group IDs and source hashes to exactly one role: `development`, `measurement_validation`, or `independent_evaluation`. Reject overlap with the development manifest and reject duplicate source groups. Keep independent evaluation records in a separate registry namespace/database.
3. **Source provenance:** hash-verified HDF5, execution, runner, model/XML, native mapping, capture configuration, and protocol-specific intervention/action channels. Preserve the exact missing fields and unsupported conditions. The adapter emits observations only; it does not consume reviewer data.
4. **Sealed prediction stage:** frozen Checker/configuration and extraction versions consume only source measurements. A prediction ledger binds every eligible and abstained case to source, protocol, code, environment, and configuration hashes. Seal its complete hash and timestamp before reference access.
5. **Separate reference and review stage:** independently recruited qualified reviewers receive blinded source evidence, not predictions or condition/method identity. Capture eligibility, prior exposure, independent judgments, event times, citations, indeterminate values, and authorized adjudication receipts in a separate store. Human judgments never enter the extractor or Checker inputs.
6. **Admission stage:** a separate verifier checks the protocol/cohort receipts, prediction seal ordering, full provenance, independent review receipt, evidence citations, and every existing physical gate. Admission is a derived result of these verified artifacts, never a caller-set boolean. Any missing receipt, provenance field, required measurement, or gate remains blocked.

The current Task 8C recorder does contain 10 settling-action values, 247 stationary-hold action values, and per-native-sample action indices. RegistryV3 2.1 validates their alignment through the recovered adapter but does not expose the action arrays as measurement citations. Those fixed capture actions are not a general deployed-policy output/action trace for a naturally occurring failure. The source has no dedicated measured external-intervention force/time series and no per-sample calibrated uncertainty bounds. It records raw contact-force vectors, but their physical convention and relationship to load-bearing support are not independently validated. Saved observations are 50 ms apart; native physics samples exist at 2 ms, but the frozen Checker interface consumes the saved-frame sequence and does not turn intermediate samples into new Checker frames. Neither a runner hash nor a contact-force value substitutes for an intervention measurement, uncertainty model, or independent physical interpretation.

The 2.1.0 path technically verifies source hashes, source-manifest and runner bindings, object/model/body identity, frame/sample mapping, timestamps, contact completeness, and exact citations. It does **not** independently validate any gate above. Schema validity, source verification, and citation resolution are necessary technical checks, not scientific admission.

## Minimum implementation before any future admission study

- Freeze and approve the protocol before source selection; define the external-perturbation measurement estimand separately from policy-failure performance.
- Preserve RegistryV3 2.1.0 as development-only; implement the separate 3.0.0 cohort/receipt architecture above without modifying the frozen Checker or admission gates.
- Extend source provenance to record the actual intervention input and timing if the target event depends on external force; otherwise scope claims to observed outcomes, not applied-force magnitude.
- Add a separate uncertainty/calibration artifact and a reviewable temporal coverage/abstention representation. Do not fill missing frames or infer load-bearing support from force values.
- Implement independent source-group enrollment, prediction sealing, reference separation, and authorized gate-review receipts before any evaluation run.
- Validate the nine gates individually on data outside all development groups. A controlled external-force cohort can support measurement/event-extraction validation only. R1 policy-failure claims require a distinct naturally occurring policy-execution cohort with action/trajectory provenance.

The candidate precision designs in [the prospective protocol](../task8c_r1v3_adapter/PROSPECTIVE_VALIDATION_PROTOCOL.md) are planning alternatives, not approved sample sizes. A 12–20 matched-group one-week effort is, at most, an exploratory measurement-validation pilot with wide uncertainty. It cannot support confirmatory Checker performance or physical admission.
