# Compatible database extension

Preserve the Phase 5A evidence table, Record 1.0.0 envelope, content IDs, immutable triggers, requirement binding and canonical JSON. Add namespaced `rag_*` extension tables to the same SQLite database. Keep SQLite user_version=1 so the existing Registry can reopen the database. Track extension migrations separately, transactionally, in `rag_migrations`; unsupported extension versions fail closed. Migration never rewrites evidence IDs or prior code.

`rag_units` binds exactly one existing evidence ID to deterministic searchable text, frame bounds, task, type, stratum, parent execution/object/window identity and build policy version. FTS5 indexes suitable source descriptions and task instructions, not copied raw arrays. `rag_jobs` stores per-execution input/policy digests and completion state. Per-execution atomic insertion is the resume boundary. `rag_builds` stores versioned content-addressed build snapshots. Failed jobs are logged; incomplete transactions roll back. Immutable evidence is deduplicated by Phase 5A IDs.

A migration can attach to an existing 5A SQLite copy; its evidence IDs remain unchanged. The production index starts with the existing evidence schema and populates all four reader-supported development executions. Old 5A retrieval and GSN code are preserved. New retrieval performs indexed SQL selection before integrity and capability checks and uses existing coverage semantics. No GSN generation or checker changes occur.

Initial units: one set of source-bound execution/task/requirement/identity/surface/calibration/limitation documents per object; discrete saved-state windows of at most 32 frames for pose, contact, native geometry, robot state, timestamps and camera references. All five reader-validated objects are included regardless of applicability. Frame-window availability does not prove continuous physical coverage. The complete 161-ID native map is retained in provenance; it is not a claim that every LIBERO geometry supports empirical checking.

R1 version 2.0.0 remains the retrieval context. AI reference proposals are separately attributed, provisional judgments. Human references are absent. Legacy checker summaries may be indexed as explicitly attributed documents with their original requirement binding; they are never reinterpreted as v2 judgments. Large payloads remain outside SQLite/Git. Optional embeddings are unnecessary until text/metadata retrieval exhibits an evidenced gap; no hosted API or model download is used.

Extension migration 1.1.0 adds `rag_catalog` and its separate FTS table. It explicitly stores historical inventory metadata, not measurement Record envelopes. 1.0.0 to 1.1.0 is an additive transaction; unsupported versions fail closed and read-only opens require migration first. SQLite core user_version and evidence Record schema stay at 1/1.0.0. Both old Registry reopen and migration-preserved IDs are tested.
