# PR #53: changes for the review of November 23

Each point of Nikta's review, what changed, and the test that covers it. No GPU inference and no review judgment was added. The frozen protocol is unchanged in design: same 3 cases, same methods, prompts, settings and measures. The Qwen prompts are byte-identical to the first version of this PR; only the revision-request digest in the stage 1 batch changed, because the approval note now points to the hand-recorded approvals.

## 1. Review-form validation

`score.py` writes no comparison unless the form has exactly the expected columns, exactly one row per review item (a duplicate, missing or unexpected blind ID is refused), an allowed value in every answer column, the reviewer, an ISO review date and the exposure declaration on every row, a description for every "yes" to a new problem, and one ISO freeze timestamp shared by all rows. It also checks that the sealed key lists exactly the revised outputs, is bound to their saved results by digest, and that no review item changed after the packet was built. Any problem stops the run, lists every problem, and writes nothing.

Tests: `DryRun.test_invalid_review_forms_are_refused` (blank, missing answer, bad value, duplicate ID, missing row, unexpected ID, no reviewer, no exposure declaration, bad date, mixed or missing freeze timestamp, undescribed new problem, wrong columns) and `test_changed_items_key_or_responses_are_refused`.

## 2. Qwen outcome accounting

All 9 requests always get a result record. Missing outputs, no-reply outputs, abstentions and invalid outputs stay in the denominators. Unknown run IDs, a request answered more than once, attempts made for another input and misnumbered attempts are refused before anything is used.

Tests: `test_each_output_path`, `test_all_nine_requests_are_accounted_for`, `test_bad_stage1_responses_are_refused`, `test_scores_worked_out_by_hand` (9 Qwen outputs: 3 revised, 1 abstained, 4 invalid, 1 missing).

## 3. Experimental provenance

Both GPU stages pass the same checks: user, system and sent-message digests per attempt, reply digests, the frozen client settings (model, temperature, max_tokens, timeout, extra parameters, system message), one model revision per stage, and no scripted replies from the command line. The stage 1 batch must use the frozen revision prompt and the stage 2 batch the frozen Critic prompt. `score.py` re-derives everything it uses: stage 1 equals a fresh build, the saved Qwen results and second Critic batch are exactly what the stage 1 responses give, each second-review request is the original argument or the re-criticism request of its saved result, and each second review matches the input its reply was made for. `RQ4_PROVENANCE.json` records prompts, model, settings, model revisions and file digests.

Human provenance of the finding approvals: approvals are no longer generated by code. `FINDING_APPROVALS.csv` was written blank by `build_approval_form.py`, one row per finding bound to its Critic report by digest. Alex Hashemi read the three findings and filled the decision, his name, the date (2026-11-23) and the attestation sentence by hand. The code only reads and checks this file. It refuses a missing, repeated, changed, unsigned, undated or unattested row, a case without exactly one approval, and an approval that is not the finding the fixed rule names. The approver wrote the planted defects, so he is not independent; this is stated in the protocol.

Tests: `Approvals` (11 kinds of bad rows, approval off the fixed rule, missing or malformed file), `Inputs.test_recorded_human_approvals`, `test_model_identity_and_settings_are_checked`.

## 4. Blinding and result preservation

Review items, the review manifest and the blank form contain no method name, run ID, output ID or justification; the mapping exists only in `experiment/sealed/REVIEW_KEY.json`. No builder changes a saved file silently: a differing fresh build writes nothing and lists the files. Stage 1 can be rebuilt (`--rebuild`) only while no stage 1 response or Qwen result exists. Saved Qwen results, the second Critic batch, review items, manifest and key are never changed. The review form is written once, blank. `score.py` never changes an existing output without `--replace-outputs`. A completed approval form is never overwritten.

Tests: `test_review_items_are_blinded`, `Protection`, `test_outputs_are_not_overwritten`, `test_pre_review_writes_facts_only`.
